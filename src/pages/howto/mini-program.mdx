export const apiJs = `// skills/promptSkill/apis/searchPrompts.js
async function searchPrompts({ keyword, tool }) {
  const list = await queryPrompts({ keyword, tool }) // 换成你自己的取数：wx.request 或云函数

  if (list.length === 0) {
    return {
      isError: false,
      content: [{ type: 'text', text:
        '没有找到相关提示词，已附上热门提示词。' +
        '请先告诉用户没找到，再引导用户从热门提示词里挑一条。' +
        '不要用相同关键词再调本接口。' }],
      structuredContent: { items: await queryPrompts({}) },
    }
  }

  return {
    isError: false,
    content: [{ type: 'text', text:
      '找到 ' + list.length + ' 条提示词。请展示列表卡片，并用一句话请用户选一条查看全文。' }],
    structuredContent: {
      items: list.map((p) => ({ promptId: p.id, title: p.title, tool: p.tool })),
    },
  }
}

module.exports = searchPrompts`;

## 让每个内容页能被直接打开

爬虫访问小程序页面时，UA 是 `mpcrawler`，场景值是 1129 <Src ids="07-S31" />。它会直接打开某个页面路径。官方的要求是 <Src ids="07-S31" />：

- **参数都放在 URL 里。** 页面要能直接打开，别依赖上一页传来的全局变量。
- **跳转优先用 `navigator` 组件。**
- **参数不要塞 JSON。**
- **必要时才要求登录授权。**

## 新内容上线后，推给微信搜索

`submitpages` 接口把页面路径、参数和正文推给微信搜索 <Src ids="07-S32" />。文档说「推送的内容将会被用于微信搜索结果展示」。它只能在服务器上调，不能在小程序前端调，也不支持第三方平台调用 <Src ids="07-S32" />。

<Copy id="mp-push" title="push-wxsearch.mjs（Node 18 以上）" lang="js" code={pushScript} />

字段都按官方文档填 <Src ids="07-S32" />：

- **先推审核环境。** `wxsearch_testcpdata` 只用来审核和校验格式，不在搜索结果里展示。确认无误再推 `wxsearch_cpdata`。
- **`path` 以 `pages/` 开头。** `path` 加 `query` 唯一确定一个页面，相同就覆盖更新。

## 让小微调用你的小程序：AI 开发模式

这是国内少有的、有官方规则可依的「让 AI 推荐我」通道。用户在微信的小微入口提问，平台会「根据开发者SKILL的描述调用」你的小程序 <Src ids="07-S35" />。SKILL 没覆盖的需求，交给小微的「AI页面交互模式」<Src ids="07-S35" />。

谁能用到（截至 2026-11）：iOS 和 Android 微信 8.0.79 及以上、有小微入口的用户 <Src ids="07-S35" />。2026-11-11 起开放微信评测和代码提审 <Src ids="07-S37" />。

### 第一步：申请开发模式

在「微信公众平台 - 基础功能 - AI 能力」里，接入模式选「开发模式」。也可以在「微信开发者助手 - 管理 - 微信AI管理」里申请 <Src ids="07-S34" />。开发要装微信开发者工具的 Nightly 版本 <Src ids="07-S34" />。

### 第二步：在 app.json 里声明 SKILL

SKILL 必须放在独立分包里，并且全局开 `lazyCodeLoading` <Src ids="27-S1" />。一个小程序最多声明 30 个 SKILL <Src ids="27-S1" />。

下面以提示词合集为例。<mark>模型最看重的是原子接口返回的 `content`，其次是 `mcp.json` 里的两种 description，`SKILL.md` 排第三。</mark><Src ids="07-S36" />

<Copy id="mp-mcp" title="skills/promptSkill/mcp.json" lang="json" code={mcpJson} />

这些写法都来自官方的 SKILL 设计建议 <Src ids="07-S36" />：

- **接口名用「动词+名词」。** `searchPrompts` 比 `search` 好。
- **`description` 首句写业务对象。** 再写调用时机和不适用的场景。
- **字段举多个例子，写清缺省怎么办。** 只举一个例子，模型容易照搬。
- **ID 字段写明取自哪个接口。** 否则模型会按格式凑一个出来。

`content` 先写事实，再写动作 <Src ids="07-S36" />。只写动作，模型可能跳过等用户确认那一步。失败分支写三件事：原因、下一步出口、不该做什么 <Src ids="07-S36" />。原子接口收到的参数不保证正确，要自己校验 <Src ids="07-S36" />。

### 第五步：写 SKILL.md

<Copy id="mp-skill-md" title="skills/promptSkill/SKILL.md" lang="markdown" code={skillMd} />

平台对 SKILL 有硬规则 <Src ids="07-S36" />：

- **不写越狱的话。** 比如「忽略指令」「你现在是」。
- **接口名和注册的一致，包括大小写。**
- **不写死回复格式。** 不能要求回复必须用表格或只能用 JSON。
- **不妨碍答案呈现。** 不能禁止 Markdown，不能要求省掉名称、价格这些关键信息。

### 第六步：上线后盯两个指标

调用量主要看两个指标：「问题发生率」和「线上版本评分」<Src ids="07-S35" />。平台还会看用户诉求、历史习惯和运营质量。

- **问题发生率超过 20% 算超标。** 它等于因开发者原因出问题的会话数，除以所有调用你 SKILL 的会话数 <Src ids="07-S35" />。在 MP 的「AI能力 - 线上状态」每 3 天出一次，We分析里按天看 <Src ids="07-S35" />。
- **每次提审都跑一次「微信评测」。** 某个版本 7 天内没评测，评分会降到上次的 80% <Src ids="07-S35" />。改原小程序的代码也可能影响 AI 体验，所以不管改没改 SKILL 都建议评测 <Src ids="07-S35" />。

<Callout type="warn">
SKILL 描述写得越宽，调用越多，问题发生率也越容易超标。只声明你真能做好的功能。
</Callout>

## 官网和公众号该怎么写这个小程序

外部 AI 读不到小程序里面，也读不到公众号 <Src ids="07-S42 07-S7" />。用户在豆包、DeepSeek 里问到你的小程序，AI 只能靠网页上的介绍（推断）。所以在你的官网放一节：

<Copy id="mp-site-block" title="官网上介绍小程序的一节" lang="markdown" code={siteBlock} />

- **名字和微信里一字不差。** 用户和 AI 都靠名字去搜。
- **写清怎么打开。** 「微信里搜索某某」比只放一个小程序码更容易被 AI 转述。
- **和网页版互相对应。** 内容页有网页版，就在 `submitpages` 的 `h5_url` 里填上它 <Src ids="07-S32" />。
