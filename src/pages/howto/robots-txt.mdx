export const uaScript = `#!/usr/bin/env bash
# 用法：bash check-ai-ua.sh https://<你的域名>/<某个内页>/
URL="$1"
if [ -z "$URL" ]; then echo "用法：bash check-ai-ua.sh <要测的网址>"; exit 1; fi

while IFS='|' read -r name ua; do
  [ -z "$name" ] && continue
  code=$(curl -s -o /dev/null -w '%{http_code}' --max-time 15 -A "$ua" "$URL")
  printf '%-18s %s\\n' "$name" "$code"

export const robotsCheck = `# 用法：python3 robots_check.py https://<你的域名> /<某个内页>/
import sys, urllib.request, urllib.robotparser
site, path = sys.argv[1].rstrip("/"), sys.argv[2]
# 自己下载 robots.txt：Python 默认的 UA 常被 CDN 拦成 403，robotparser 会因此把所有爬虫判成 BLOCK
req = urllib.request.Request(site + "/robots.txt", headers={"User-Agent": "Mozilla/5.0 robots-check"})
try:
    lines = urllib.request.urlopen(req, timeout=15).read().decode("utf-8", "replace").splitlines()
except urllib.error.HTTPError as e:
    sys.exit(f"robots.txt 返回 {e.code}。404 表示没有 robots.txt，等于全部允许。")
rp = urllib.robotparser.RobotFileParser()
rp.parse(lines)
for ua in ["Googlebot", "Bingbot", "Applebot", "Baiduspider",
           "OAI-SearchBot", "Claude-SearchBot", "PerplexityBot", "MistralAI-Index", "meta-webindexer", "DuckAssistBot",
           "ChatGPT-User", "Claude-User", "Perplexity-User", "MistralAI-User",
           "Google-Extended", "GPTBot", "ClaudeBot", "Applebot-Extended", "MistralAI-Training",
           "meta-externalagent", "CCBot", "Bytespider"]:
    print(f"{ua:20} {'allow' if rp.can_fetch(ua, site + path) else 'BLOCK'}")`;

## 第一步：复制这份模板

<Copy id="robots-template" title="public/robots.txt（Astro 站放在 public/ 下，构建后就在根目录）" code={robotsTemplate} />

每组的依据：

- **传统搜索全部放行。** AI Overviews 和 AI Mode 用 Google 的索引 <Src ids="02-S9" />，Copilot 用 Bing 的 <Src ids="02-S20" />。Brave 只抓 Googlebot 能抓的页面 <Src ids="02-S32" />，Claude 又用 Brave 搜索 <Src ids="02-S30" />。
- **AI 搜索索引全部放行。** 挡了 OAI-SearchBot 就不会出现在 ChatGPT 搜索回答里 <Src ids="02-S1" />。Anthropic、Perplexity、Mistral、Meta、DuckDuckGo 的文档结构相同 <Src ids="02-S25 02-S33 02-S39 02-S37 02-S40" />。
- **用户触发放行。** 多数写明 robots.txt 可能不适用 <Src ids="02-S1 02-S33" />。Anthropic 说挡了 Claude-User 会降低用户主动查询时的可见度 <Src ids="02-S25" />。
- **训练类自己选。** 各家都写明，关掉训练不影响搜索展示 <Src ids="02-S1 02-S25" />。放行训练能不能让模型记住你，还没有可靠数据。

一组里写多个 `User-agent:` 行、共用规则，是 RFC 9309 定义的写法 <Src ids="02-S27" />。

<Callout type="warn">
写了专门组的爬虫，不再读 `User-agent: *` 组。你在 `*` 组里写的 `Disallow: /admin/`，对 Googlebot、OAI-SearchBot 都不生效。私有路径要在每一组里都写一遍。
</Callout>

## 第二步：想清楚 Google-Extended

<mark>Google-Extended 不是单纯的训练开关。</mark>它同时管 Gemini 训练，和 Gemini 应用里的实时引用 <Src ids="02-S15" />。挡了它，你就不在 Gemini 应用的引用里。它不影响 Google 搜索，也不影响 AI Overviews <Src ids="02-S15" />。

一项 SIGIR 2026 的研究看到：挡了 Google-Extended 的网站，在 Gemini 里一次都没被引用 <Src ids="01-S18" />。

还有一个新坑。2026-10-30 出现了跨厂商的训练令牌 `__usage_ai-training` <Src ids="02-S27" />。Google 计划 2027 年支持它 <Src ids="02-S15" />。到时候，如果你用它退出训练，又没单独写 Google-Extended，Google 会当作你挡了 Google-Extended <Src ids="02-S14" />。单独允许了 Google-Extended 的网站，仍能在 Gemini 应用里被引用 <Src ids="02-S14" />。

所以模板里第 4 段单独写了 `User-agent: Google-Extended` 和 `Allow: /`。选了「禁止训练」也别删它，除非你确实不想出现在 Gemini 里。

关于 `__usage_ai-training` 还要知道 <Src ids="02-S27" />：

- **`*` 组不算。** IETF 草案规定 `User-agent: *` 不能被解释成匹配这个令牌。
- **没写就是没表态。** 不是同意，也不是拒绝。
- **它不管抓取。** 想限制抓取，仍要写各爬虫自己的组。
- **只是草案。** 个人提交的 Internet-Draft，没有正式标准地位，2027-05-03 到期。

各家什么时候执行（截至 2026-11）：Anthropic 已开始，Microsoft 2027-02-01 起，Google 2027 年，OpenAI 只说未来几个月 <Src ids="02-S28 02-S29" />。Anthropic 的规则是：写了 ClaudeBot 组就以它为准 <Src ids="02-S25" />。

## robots.txt 管不到的事

- **退出 ChatGPT 搜索：** 用 `noindex`，并让爬虫能抓到这个页面 <Src ids="03-S6" />。
- **退出 AI Overviews 和 AI Mode：** 用 Search Console 的 Search generative AI 开关 <Src ids="02-S11" />。
- **Bing 的 grounding：** 只有页面级设置，2027-02-01 起执行 <Src ids="02-S20" />。

## 卡住了？

<Q q="robots_check.py 显示所有爬虫都是 BLOCK">
先用浏览器打开 `https://<你的域名>/robots.txt`，看是不是真的写了 `Disallow: /`。没写的话，多半是 CDN 把脚本的请求拦了。确认你用的是本页的脚本，它会自己带 UA 下载。
</Q>

<Q q="改了 robots.txt，线上还是旧的">
先看是不是缓存，`curl -sI` 看响应头里的缓存字段。再看 Cloudflare 的托管 robots.txt 是否开着，它会在前面插内容 <Src ids="03-S17" />。
</Q>

<Q q="我想挡 Bytespider，会不会影响豆包">
没查清。头条搜索站长平台写明 Bytespider 是头条搜索的爬虫，文档没提豆包 <Src ids="07-S27" />。挡了它，头条搜索一定爬不到你；豆包受不受影响，没有资料。GitHub 的 robots.txt 整站禁止了它 <Src ids="03-S65" />。要挡就把模板第 1 段里的 `User-agent: Bytespider` 删掉，在末尾加一组 `User-agent: Bytespider` 和 `Disallow: /`。
</Q>

<Q q="robots.txt 全对，curl 还是 403">
robots.txt 不会让服务器返回 403，它只是一份请求。403 来自 CDN 或防火墙，去看 [Cloudflare 的 How-to](/howto/cloudflare-bots/)。
</Q>
